The DOM is the live object model of the page. Frameworks abstract it, but every React error you'll ever debug makes more sense when you understand what the framework does underneath.

## Selecting and changing

```js
const btn = document.querySelector("#submit");
btn.textContent = "Saving…";        // safe text
btn.classList.add("is-loading");    // style via classes, not inline
```

Prefer `textContent` over `innerHTML` with anything user-provided — `innerHTML` is an XSS hole.

## Events and delegation

Attaching one listener to a container instead of one per item is the pattern behind every list UI:

```js
document.querySelector("#todos").addEventListener("click", (e) => {
  const item = e.target.closest("li");
  if (!item) return;
  item.classList.toggle("done");
});
```

Works for items added later, too — no re-binding.

## A vanilla todo list (the exercise)

```js
const form = document.querySelector("#add-form");
const list = document.querySelector("#todos");

form.addEventListener("submit", (e) => {
  e.preventDefault();
  const input = form.querySelector("input");
  const li = document.createElement("li");
  li.textContent = input.value.trim() || "Untitled";
  list.append(li);
  form.reset();
});
```

Build this from memory. Then add filtering (all/active/done) and a delete button — still zero frameworks.

## Common mistakes interviewers spot

- 100 listeners instead of 1 delegated listener
- `innerHTML` with user input (XSS) instead of `textContent`
- Assuming `querySelectorAll` results update automatically
