JavaScript is single-threaded, so all waiting (network, timers, files) happens asynchronously. Promises and async/await are how modern code stays readable while doing many things at once.

## The mental model in one paragraph

The call stack runs your code. Waiting work (fetch, timers) is handed to the browser; when it finishes, the callback is queued and the event loop pushes it onto the stack **only when the stack is empty**. That's why a `while(true){}` blocks everything — the loop can't run.

## async/await with real error handling

```js
async function loadUser(id) {
  try {
    const res = await fetch(`/api/users/${id}`);
    if (!res.ok) throw new Error(`HTTP ${res.status}`); // fetch doesn't throw on 404!
    return await res.json();
  } catch (err) {
    console.error("loadUser failed:", err);
    throw err; // let the caller decide UI
  }
}
```

The `res.ok` check is the most-forgotten line in JavaScript.

## Parallel vs sequential — the performance difference

```js
// ❌ 3 round-trips, one after another
const a = await fetchA(); // 300ms
const b = await fetchB(); // 300ms
const c = await fetchC(); // 300ms

// ✅ all three at once, ~300ms total
const [ra, rb, rc] = await Promise.all([fetchA(), fetchB(), fetchC()]);
```

`Promise.all` fails fast on any rejection; `allSettled` waits and reports each outcome — use it when partial results are fine.

## Aborting: effects and timeouts

```js
const ctrl = new AbortController();
setTimeout(() => ctrl.abort(), 5000); // timeout
const res = await fetch(url, { signal: ctrl.signal });
```

## Practice — do these, don't just read

1. Fetch data from a public API (e.g. GitHub users) and render a list with loading and error states.
2. Convert a callback-style function to Promise-based, then to async/await — feel the readability change.
3. Run 3 fetches in parallel with `Promise.all`, then handle partial failure with `allSettled`.

## Common mistakes interviewers spot

- `.then` without error handling (unhandled rejections)
- `await` inside loops where `Promise.all` was intended
- Forgetting the `res.ok` check after fetch
