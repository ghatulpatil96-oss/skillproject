APIs are where most bugs hide, and API tests run 100× faster than UI tests. Postman turns API testing into a systematic, shareable practice.

## The negative-path mindset

Happy paths break rarely; boundaries break constantly. For any endpoint, test:

```text
✅ 200  valid request
❌ 400  missing field / wrong type / empty body
❌ 401  no token · expired token · someone else's token
❌ 404  id that doesn't exist · someone else's resource (IDOR!)
❌ 409  duplicate create
❌ 422  boundary values (score: -1, 101, "abc")
```

IDOR (accessing another user's resource by changing the id) is the highest-value manual test a junior can run.

## Assertions in the Postman sandbox

```js
pm.test("status is 201", () => pm.response.to.have.status(201));

pm.test("job has id and title", () => {
  const job = pm.response.json();
  pm.expect(job).to.have.property("id");
  pm.expect(job.title).to.eql("Backend Dev");
});
```

## Chaining: the realistic workflow

Login → create → read → update → delete, passing values between requests:

```js
// login test script: capture the token
pm.environment.set("token", pm.response.json().token);

// later requests use the header
Authorization: Bearer {{token}}
```

Export the collection → run it from the CLI in CI:

```bash
npx newman run skillbridge-api.json -e dev-env.json
```

1. Test a public API with 20 requests: positive + negative paths for each endpoint.
2. Chain a full workflow: login → create → read → update → delete, using environment variables.
3. Export the collection and run it with Newman; add it to a GitHub Actions workflow.
