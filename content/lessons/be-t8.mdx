Authentication is where security mistakes live. Password hashing, session tokens, and cookie flags are not optional details — they're what interviews probe and what attackers probe harder.

## Passwords: slow hashes with salt

```js
import { randomBytes, scryptSync, timingSafeEqual } from "node:crypto";

function hashPassword(password) {
  const salt = randomBytes(16).toString("hex");
  const hash = scryptSync(password, salt, 64).toString("hex");
  return `${salt}:${hash}`;
}

function verify(password, stored) {
  const [salt, hash] = stored.split(":");
  const candidate = scryptSync(password, salt, 64);
  return timingSafeEqual(candidate, Buffer.from(hash, "hex"));
}
```

scrypt/bcrypt/argon2 are deliberately **slow** — that's the feature. Per-user salt kills rainbow tables. `timingSafeEqual` kills timing attacks. Plain SHA-256 is too fast: GPUs try billions per second.

## Sessions vs JWT

| | Session cookie | JWT |
|---|---|---|
| State | Server-side store | Self-contained, signed |
| Revocation | Delete the session | Hard (needs a blocklist) |
| Best for | Classic web apps | Service-to-service, short-lived tokens |

SkillBridge (this very site) uses a signed, self-contained cookie: HMAC over `{userId, exp}`.

## The cookie flags that matter

```js
res.cookies.set("sb_session", token, {
  httpOnly: true,   // JS cannot read it → XSS can't steal it
  secure: true,     // HTTPS only
  sameSite: "lax",  // CSRF protection for most cases
  maxAge: 30 * 86400,
});
```
