DSA interviews are a filter, not the job — but the filter is real. Focused hours on patterns beat scattered hours on random problems.

## The patterns that cover most questions

**Two pointers** (sorted arrays, pairs):

```js
function hasPairSum(arr, target) {        // arr sorted
  let lo = 0, hi = arr.length - 1;
  while (lo < hi) {
    const s = arr[lo] + arr[hi];
    if (s === target) return true;
    s < target ? lo++ : hi--;
  }
  return false;
}
```

**Frequency map** (counts, duplicates, anagrams):

```js
const counts = new Map();
for (const ch of s) counts.set(ch, (counts.get(ch) ?? 0) + 1);
```

**Sliding window** (longest substring with constraint):

```js
function longestUnique(s) {
  const seen = new Map();
  let start = 0, best = 0;
  for (let i = 0; i < s.length; i++) {
    if (seen.has(s[i]) && seen.get(s[i]) >= start) start = seen.get(s[i]) + 1;
    seen.set(s[i], i);
    best = Math.max(best, i - start + 1);
  }
  return best;
}
```

Plus: binary search (on the answer, not just arrays), BFS/DFS on trees/graphs, and stack patterns (matching, monotonic).

## The method interviewers grade

UMPIRE-style, out loud: **U**nderstand (clarify, constraints) → **M**atch (which pattern?) → **P**lan (steps before code) → **I**mplement (clean) → **M**onitor (test, edge cases). The narration is the product.
