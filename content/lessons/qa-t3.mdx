Test automation is programming. JavaScript fundamentals — especially async — are the engine under Playwright and Selenium; everything else is syntax.

## Async is not optional

Every browser action (click, navigate, wait) is asynchronous. Testers who don't understand promises write the flaky suites everyone hates:

```js
// ❌ looks like it works, races the page
const el = await page.$("#submit");   // element handle found...
el.click();                            // ...but the page may re-render first

// ✅ locator-based: Playwright resolves it at action time
await page.click("#submit");
await expect(page.getByRole("heading", { name: "Order placed" })).toBeVisible();
```

## Selectors that survive redesigns

```js
page.getByRole("button", { name: "Checkout" })  // best: semantic
page.getByTestId("checkout-btn")                // good: stable contract
page.getByText("Place order")                   // okay: copy can change
page.click(".btn-primary.mt-4")                 // ❌ styling changes weekly
```

`data-testid` is a contract between app code and test code — cheap insurance.
