JavaScript fundamentals power everything else on this roadmap. Variables and types look simple; the edge cases (coercion, hoisting, closures) are exactly what interviewers test.

## const, let, and scope

Use `const` by default, `let` when reassigning, `var` never. Both `let`/`const` are block-scoped:

```js
{
  const a = 1;
  let b = 2;
}
// a and b don't exist here — block scope
```

## Primitives vs references — the classic trap

Objects are assigned by **reference**; copying a variable copies the pointer, not the object:

```js
const a = { name: "Ananya" };
const b = a;          // same object!
b.name = "Riya";
console.log(a.name);  // "Riya" — surprise

const c = { ...a };   // shallow copy: top level only
```

## Closures: functions remember their birthplace

A function keeps access to variables from where it was **defined**:

```js
function makeCounter() {
  let count = 0;
  return () => ++count;  // closes over `count`
}
const next = makeCounter();
next(); // 1
next(); // 2 — `count` is private and alive
```

This one pattern explains React hooks, module privacy, and half of interview curveballs.

## The array methods you'll use hourly

```js
const active = users
  .filter(u => u.active)          // keep some
  .map(u => u.name)               // transform each
  .sort();                        // or reduce for anything
```
