Backend JavaScript has different priorities than frontend: error handling, streams, and module systems matter more than DOM tricks. Solidify the core before touching frameworks.

## Errors are part of your API surface

```js
class ValidationError extends Error {
  constructor(fields) {
    super("Invalid input");
    this.name = "ValidationError";
    this.fields = fields;
  }
}

try {
  validate(body);
} catch (err) {
  if (err instanceof ValidationError) {
    return res.status(400).json({ errors: err.fields });
  }
  throw err; // unknown → 500 path
}
```

Custom error classes let handlers map domain failures to honest HTTP codes.

## Async in servers: parallel and bounded

```js
// independent work → parallel
const [user, orders] = await Promise.all([
  db.users.get(id),
  db.orders.byUser(id),
]);

// unbounded parallel on 10k items = explode; batch it
for (const batch of chunk(items, 50)) {
  await Promise.all(batch.map(process));
}
```

## Configuration lives in the environment

```js
const PORT = process.env.PORT ?? 3000;
const DB_URL = process.env.DATABASE_URL; // required — fail fast
if (!DB_URL) throw new Error("DATABASE_URL missing");
```

Secrets never go in code. `.env` locally (gitignored), platform env vars in production.
