Python is the analyst's automation layer. Notebooks are for exploration; scripts are for repeatable work — knowing when to use which is professionalism.

## The syntax that covers 80% of analysis

```python
sales = [120, 340, 90, 250]

big = [s for s in sales if s > 100]        # comprehension
totals = {region: sum(vals) for region, vals in by_region.items()}

def monthly_summary(rows, tax=0.18):
    """Net after tax, rounded — docstrings are free documentation."""
    return round(sum(rows) * (1 - tax), 2)
```

## The notebook workflow (Colab = zero setup)

```python
# cell 1: load
import pandas as pd
df = pd.read_csv("sales.csv")

# cell 2: explore
df.head(), df.shape, df.describe()

# cell 3: one question → one answer
df.groupby("region")["amount"].sum().sort_values(ascending=False)
```

One cell, one idea. Notebooks that run top-to-bottom are reproducible; notebooks run out of order are science experiments.

## From notebook to script

```python
# summarize.py — parameterized, runnable, schedulable
import sys
import pandas as pd

def main(path: str) -> None:
    df = pd.read_csv(path)
    summary = df.groupby("region")["amount"].sum()
    print(summary.to_markdown())

if __name__ == "__main__":
    main(sys.argv[1])
```

Same analysis, but now `python summarize.py sales.csv` runs anywhere — a cron job, a teammate's laptop, CI.
