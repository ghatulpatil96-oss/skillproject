More than half of all web traffic is mobile. Responsive design means a single codebase that adapts from a 360px phone to a 4K monitor — using fluid sizing and media queries, not separate mobile sites.

## Mobile-first is a CSS ordering strategy

Write base styles for the smallest screen, then layer on complexity with `min-width` queries. You'll write less overrides and nothing gets forgotten on small screens.

```css
/* base: mobile */
.nav { display: none; }
.nav.open { display: flex; flex-direction: column; }

/* 768px and up: horizontal nav */
@media (min-width: 768px) {
  .nav { display: flex; }
  .nav.open { flex-direction: row; }
}
```

## Relative units over fixed pixels

`rem` scales with the user's root font size (accessibility!), `%` and `vw` scale with the container. Pixels are fine for borders and shadows, not for type and layout.

```css
.card {
  font-size: 1rem;        /* respects user settings */
  padding: clamp(16px, 4vw, 32px); /* fluid, with sane bounds */
  max-width: 65ch;        /* readable line length */
}
```

## Test like a user, not like a designer

DevTools device emulation catches layout breaks, but also test: touch targets (min 44×44px), reduced motion (`prefers-reduced-motion`), and real devices when possible.

## Practice — do these, don't just read

1. Take your Stage-1 news homepage and make it perfect at 360px, 768px, and 1440px.
2. Build a responsive navigation that collapses into a hamburger below 768px — keyboard accessible, not just click.
3. Emulate `prefers-reduced-motion: reduce` in DevTools and add appropriate fallbacks for your animations.

## Common mistakes interviewers spot

- Designing at 1920px and never testing below 1024px
- Fixed heights that clip text when font size changes
- Touch targets smaller than 44×44px
