Dashboards are analysis that outlives you: the test is whether a manager gets Monday-morning answers without pinging you.

## Model for BI, not for export

Star-schema thinking — even in a simple tool:

- **Facts**: the events (orders, sessions) — rows you aggregate
- **Dimensions**: the slices (date, region, product) — things you group by

A clean date dimension (with month/quarter columns) fixes 90% of dashboard time-trouble before it starts.

## One screen, one message per visual

```
┌──────────────────────────────────────────────┐
│ Revenue: ₹4.2Cr  ▲ +12% MoM   (the headline) │
├──────────────┬───────────────────────────────┤
│ Trend line   │  Top 5 regions (bar)          │
│ (12 months)  │                               │
├──────────────┴───────────────────────────────┤
│ Category detail table (sortable, sparse)     │
└──────────────────────────────────────────────┘
```

Top-left = the number the VP cares about. Every visual answers one question. Filters (date range, region) live in one consistent strip.

## The refresh conversation (junior analysts forget this)

A dashboard with last-quarter's data is worse than none — it lies confidently. Know and document: where the data comes from, how often it refreshes, who's alerted when the refresh fails. In Looker Studio, connect the live source (BigQuery/Sheets); in Power BI, a scheduled gateway refresh.

## Practice — do these, don't just read

1. Build a one-page sales dashboard in Looker Studio (free, Google account) from a clean dataset.
2. Add a drilldown path: region → category → product.
3. Present it to a friend for 2 minutes. If they ask "so what?" at any visual, redesign that visual.
