React is a UI library built on one idea: **UI is a function of state**. Change the state, React re-renders the affected UI. Components, props, and state are the vocabulary you'll use every day.

## Components are functions

```jsx
function Badge({ label, tone = "green" }) {
  return <span className={`badge badge-${tone}`}>{label}</span>;
}

// composition: props flow down
<Badge label="Verified" tone="green" />
```

Props are read-only. If a child needs different data, the parent passes new props — the child never mutates them.

## State changes trigger re-renders

```jsx
const [count, setCount] = useState(0);

// ❌ mutation: same array reference, React sees "nothing changed"
// items.push(newItem);

// ✅ replacement: new array reference
setItems(prev => [...prev, newItem]);
```

The rule: **state updates must be new references**. Arrays and objects get spread/`map`/`filter`, never `.push()`.

## Keys: identity in lists

```jsx
{todos.map(t => <TodoRow key={t.id} todo={t} />)}
```

Keys tell React which item is which across re-renders. Index-as-key breaks when items reorder (state attaches to the wrong rows).

## Controlled inputs

```jsx
const [email, setEmail] = useState("");
<input value={email} onChange={e => setEmail(e.target.value)} />
```

React state is the single source of truth — the input just displays it.

## Common mistakes interviewers spot

- Mutating state arrays/objects instead of replacing them
- Prop drilling 4 levels when lifting state would do
- Defining components inside other components (remounts every render)
