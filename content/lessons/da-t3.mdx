SQL is the analyst's superpower: it runs against every warehouse, BI tool, and interview panel. Zero to confident joins in a focused week.

## The shape of every query

```sql
SELECT region, product, SUM(amount) AS revenue
FROM sales
WHERE sale_date >= '2026-01-01'      -- rows in
GROUP BY region, product
HAVING SUM(amount) > 10000           -- groups in
ORDER BY revenue DESC
LIMIT 20;
```

Memorize the **order of operations**: `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER → LIMIT`. It explains why you can't use an alias in WHERE and why aggregates need HAVING.

## NULLs are not values

```sql
WHERE region IS NULL          -- ✅ (region = NULL matches nothing!)
COALESCE(region, 'Unknown')   -- default for display
```

## Joins: the daily bread

```sql
SELECT c.name, COUNT(o.id) AS orders
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
GROUP BY c.id;
```

LEFT keeps customers who never ordered (COUNT(o.id) = 0). This exact question appears in most analyst interviews.

## Window functions: the level-up

```sql
-- top 3 products by revenue per region
SELECT * FROM (
  SELECT region, product, SUM(amount) AS revenue,
         ROW_NUMBER() OVER (PARTITION BY region ORDER BY SUM(amount) DESC) AS rn
  FROM sales GROUP BY region, product
) ranked
WHERE rn <= 3;
```

Windows aggregate **without collapsing rows** — running totals, rankings, deltas all become one query.
