Node.js is JavaScript outside the browser: non-blocking I/O for high-concurrency servers. Knowing the runtime makes framework code predictable instead of magical.

## The event loop, operationally

Node handles thousands of connections on one thread by never waiting: I/O is handed off (OS/libuv), callbacks queue up, and the loop runs them when the stack empties. The killer is therefore **blocking the stack**:

```js
app.get("/report", (req, res) => {
  const sum = hugeArray.reduce(...); // 3s of CPU → EVERY request stalls
});
```

CPU-heavy work goes to worker threads or a queue; the event loop stays free for I/O.

## Core modules you'll actually use

```js
import fs from "node:fs/promises";  // promises API by default
import path from "node:path";
import crypto from "node:crypto";   // hashing, tokens

const data = await fs.readFile(path.join(process.cwd(), "data.json"), "utf8");
```

## npm without pain

- `package-lock.json` is committed — it's the reproducible build
- `npm ci` in CI (exact, clean); `npm install` locally
- Semver: `^1.2.3` = minor/patch updates OK, `~1.2.3` = patch only

## An HTTP server with zero frameworks

```js
import http from "node:http";

http.createServer((req, res) => {
  if (req.url === "/health") {
    res.writeHead(200, { "Content-Type": "application/json" });
    return res.end(JSON.stringify({ ok: true }));
  }
  res.writeHead(404).end();
}).listen(3000);
```

Build this once and Express stops being magic — it's convenience over exactly this.
