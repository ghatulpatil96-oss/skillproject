SkillBridge

A full-stack hiring platform built for tier-2/3 college students in India — where students learn from structured roadmaps, prove their skill through server-graded tests, and get hired by verified recruiters, closing the gap traditional resumes create.

At a Glance

The Problem & the Solution

Students from tier-2 and tier-3 colleges rarely get interviews because résumés carry no verifiable proof of skill, and recruiters waste time filtering unqualified applications. SkillBridge replaces the résumé-first model with a skill-first pipeline.

Feature Deep-Dive

What the Platform Does

L

Learning Roadmaps

42 MDX-rendered lessons across Frontend, Backend, Data Analyst and QA paths. Each lesson ends with an inline graded quiz; a link-checker and lesson-checker script keep content consistent (42/42 pass).

T

Verified Skill Tests

20-minute timed tests. The answer key lives in a server-only module — answers never ship to the browser. Grading, percentiles and attempt limits are all server-side.

R

Recruiter Console

Recruiters post real jobs and review an application pipeline (applied → shortlisted → challenged → interview → offer). Campus and tier information is hidden from recruiters by design to give every student a level playing field.

A

Admin Console

Admins review and verify recruiter accounts through a server-driven verification queue, keeping the marketplace trustworthy.

Security-First Design

Hardening Highlights

  • Answer-key isolation — quiz answers and explanations are imported server-only; only question stems and option labels reach the browser.
  • Signed test tickets — grading requires an HMAC ticket bound to {userId, skillId, iat}; the endpoint independently re-checks the 20-minute and 90-second time windows and reject spoofed submissions.
  • Rate limiting — 5 sign-in / sign-up attempts per 15 minutes per (IP + e-mail), throttling credential-stuffing and fake-account creation.
  • Role-gated zones with defence-in-depth — middleware blocks /recruiter, /admin and all admin APIs; server layouts independently re-check role on every request.
  • Abuse-proof signup & email — admin roles impossible to self-register; all transactional e-mail HTML is untrusted-input-escaped with CTA-link sanitisation, and has end-to-end verified.
Live-verified: every one of these controls was confirmed on the running deployment — auth redirects 401/403/407, the 6th login in a row returns 429, admin signup returns 403, and grading without a signed ticket returns 400.
